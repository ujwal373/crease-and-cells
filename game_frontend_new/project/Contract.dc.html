Integration contract

What your backend must return

The frontend never decides a question, a reward or who may join a club. It calls one object, CCApi, and draws what comes back. Today CCApi uses a built in stand in. Point it at your scraper and agent backend and keep the same shapes.

1 Swap the adapter

// index of the prototype, before anything renders
CCApi.use('http', {
  baseUrl: 'https://your-server.example',
  headers: { Authorization: 'Bearer <token>' }
});
// Back to the stand-in at any time:
CCApi.use('mock', { delay: 700, failEvery: 0 });
cc-formula.jsA small formula evaluator. Only the stand in uses it. Delete it when your server checks answers.
cc-engine.jsHolds CCApi, the mock agents and the HTTP adapter. The HTTP adapter is the only part you edit.
cc-world.jsMap, buildings, character list and paths. Pure drawing data. Never sent to the server.

2 Endpoints

VerbPathPurpose
GET/api/worldGame config, the player snapshot, and a marker for every character: new, done, locked, store, match, learn or talk.
POST/api/npcs/:npcId/encounterThe player talked to someone. The agent behind that character writes a question, a store view or a recruiter view.
POST/api/encounters/:id/answerCheck one answer. Pay once, on the first correct answer.
POST/api/encounters/:id/beginStart an exam or timed match. Re-check every requirement and the cooldown, start the cooldown, return the first question.
POST/api/encounters/:id/lessonA mentor teaches a chosen topic. Pays a small XP amount.
POST/api/facilities/:id/visitStanding in a facility. Pays points on a server rate limit, never asks a question.
POST/api/playerSave the character creator choices.
POST/api/store/buySpend coins, record ownership, equip it.
POST/api/avatar/equipChange what is worn. Only owned items.
GET/api/clubsThe seven club objects with live requirement ticks. Used by Career and the next goal line.

Character ids the frontend sends are: coach0 to coach6, akshita, tea, kit, pav, sana, rec1 to rec7 and w0 to w5. Add more by adding rows to cc-world.js.

4 What your agents should do

Unique every time. Each encounter makes a new sheet and a new target. Seed it per player, character and time so a repeat is rare. Keep the answer key. Never put the expected value or a model formula in a response. Check on the server and say only correct or not. Check by value. Run the player's formula on the sheet you made and compare the result. That accepts every valid way to write it. Teach in feedback. A wrong answer should say what Excel would show, for example the formula result or #NAME?. Match the family. Coaches always ask their own family. Wanderers and workers mix. Difficulty 1 to 3 follows the player's skill level. Pay once. The first correct answer to an encounter pays. Repeats return correct with zero rewards. Say when it is slow. The panel shows a waiting state. Aim for under 2 seconds, and fail fast with a clear message.

5 States the frontend already draws

StateWhat the player sees
Waiting for the agentA panel with the character's name, a moving bar and the line "No two are the same".
Agent or network failedA red alert with your message, a Try again button and a Back to the world button.
Wrong answerAn icon, the word Not yet, and your feedback. The player can try again for free.
Right answerA tick, the coins and XP paid, your explanation, and Ask another question.
Skill or level upA toast that is read out to screen readers.
Lobby not readyThe requirement list with a tick or a dashed circle and the words Done or Missing, and a live countdown when a cooldown is running.
Timed matchA banner with the over, the pass mark and a visible seconds clock. Relaxed timing doubles the seconds.
Session overA result card with the score and bonus, then Back to the world.

Test these without a backend: CCApi.use('mock', { failEvery: 3 }) makes every third call fail.
